# td-paintweb

Рисование с планшета поверх картинки в TouchDesigner: слои, кисть с выбором
цвета, ластик, маска источника и отдельный слой монотонного цвета с цветовой
температурой. Пикселями владеет TD, браузер — тонкий клиент с мгновенным
превью мазка.

---

## Быстрый старт: добавить в TouchDesigner

Нужен один файл — **`dist/paint_web.tox`**. Внутри него уже лежит всё: код,
шейдеры и сама веб-страница, поэтому рядом ничего раскладывать не надо.

1. Скачай `dist/paint_web.tox` (кнопка **Download** на странице файла).
2. В TouchDesigner открой свой проект и **перетащи `.tox` в сеть нод** — или
   правый клик по сети → *Add Operator* и выбери скачанный файл.
3. Всё. Компонент сам поднимает веб-сервер (у `tick` включён `start`).
4. Возьми адрес из DAT **`paint_web/server/address`** — он же печатается в
   Textport при старте. Открой этот адрес в браузере планшета (та же сеть Wi-Fi)
   или на ПК с TD.
5. Порт по умолчанию **9980**, меняется параметром `Port` на компоненте.

Ссылка на интерфейс есть и в самом компоненте: на странице параметров `Paint`
лежит адрес (`Page`) и кнопка **«Открыть интерфейс»** (`Openpage`) — она открывает
страницу в браузере на машине с TouchDesigner. Ни Textport, ни ручного набора
адреса для этого не нужно.

Проверка «на себе»: сначала открой `http://127.0.0.1:9980/` на самом ПК. Если тут
страница есть, а с планшета нет — дело в файрволе. Один раз, PowerShell от
администратора:

```powershell
New-NetFirewallRule -DisplayName "TD PaintWeb 9980" -Direction Inbound -LocalPort 9980 -Protocol TCP -Action Allow -Profile Private
```

Вне своей сети порт не пробрасывай: поставь Tailscale на ПК и на планшете и
открывай `http://<tailscale-ip>:9980/`.

Папку для данных (загрузки, медиа, временные файлы) компонент создаёт сам —
`<папка проекта>/paint`.

Куда идут пиксели: у компонента четыре выходных разъёма — `out` (готовый
композит), `outpaint` (только краска), `outmask` (маска источника) и `outcmask`
(маска слоя цвета). Чтобы отдать картинку дальше (например в `ndioutTOP`),
подключайся к разъёму компонента: провод между операторами из разных сетей TD не
проводится — это правило TD, а не ограничение компонента.

## Как это работает (коротко)

- **TD — авторитет.** Краска и маска живут в TD двумя петлями обратной связи.
  За один кадр кисть накладывает пачку до 128 штампов, а вне изменённого
  прямоугольника шейдер просто копирует предыдущее состояние.
- **Штампы едут из Python** маленьким PNG `512×1` (4 тексела на штамп), его
  читает `moviefileinTOP`. Доставка занимает два кадра: кадр пишет текстуру,
  следующий рисует — иначе шейдер успевает прочитать прежнюю.
- **Браузер получает патчи** — PNG только изменённой области, уже во время мазка,
  с частотой `Patchhz`. Тумблер `Fullframe` вместо этого шлёт целый слой
  (`Fullfps` раз в секунду, `Fulljpeg` — в JPEG): дороже по трафику, но клиенту
  не нужно попадать прямоугольником. Для видео-источника есть JPEG-прокси
  (`Proxyfps`).
- **Слои.** «Источник» — картинка или видео, показываемые через **свою** маску
  (кисть проявляет, ластик прячет). «Цвет» — ровный цвет по **своей отдельной**
  маске: в панели слоёв у него своя строка с глазом (видимость), ползунком
  «Интенсивность» и ползунком температуры 2000…10000 К с плашкой самого цвета.
  «Краска» — то, что рисуешь кистью. Порядок в панели = порядок в композите:
  источник → цвет → краска.
- **Масок две, и они разные.** У источника свой буфер (слой 2), у слоя цвета свой
  (слой 4): стереть картинку и стереть цвет можно по отдельности — то, что
  открыто для источника, не обязано совпадать с тем, где виден цвет. В TD это две
  независимые цепочки (`fbm/brushm/bufm` и `fbm2/brushm2/bufm2`), каждая со своим
  undo. Кисть по «Источнику» рисует маску источника, по «Цвету» — маску цвета, по
  «Краске» — краску; сервер говорит странице, какая маска какому слою
  соответствует (поле `usesMask`).
- **Интенсивность** каждого слоя — параметры `Srcint`, `Paintint`, `Maskint`,
  `Colorint` на компоненте и ползунок в строке слоя на странице. Видимость слоя
  цвета — отдельный тумблер `Colorvisible`, температура — `Colortemp` в Кельвинах
  (6500 — нейтрально). Цвет считается одной и той же формулой в TD и в браузере,
  поэтому ползунок показывает ровно тот цвет, что уйдёт на выход.
- **Undo/Redo** до 24 шагов: хранит TD, по маленьким областям.
- **Кнопки на странице** (блок TouchDesigner): «Пересобрать», «Проверка»,
  «Открыть на ПК», «Обновить из git» — Textport для работы не нужен. Те же
  действия есть как HTTP: `POST /api/rebuild`, `POST /api/selftest`,
  `POST /api/open`, `GET /api/address`, `GET /api/report`.
- **Отчёты TD пишет сам** на диск: `paint/td/last_build_report.txt` (отчёт
  сборки), `paint/tmp/run_summary.txt` (сводка одного шага),
  `paint/tmp/paint_web_report.json` (состояние, ошибки и предупреждения нод —
  он же отдаётся по `/api/report`). Копировать Textport вручную не нужно.

## Обновление

На странице есть кнопка **«Обновить из git»**: TD делает `git pull` в папке
исходников, пишет результат в журнал и пересобирает компонент, если файлы
изменились. Вручную то же самое — `git pull` в этом репозитории.

Если компонент вставлен из `.tox` в чужой проект, рядом с ним исходников нет: он
это видит, самовосстановление и пересборку отключает и просто работает. Чтобы
обновить такой проект, скачай свежий `dist/paint_web.tox` и перетащи его в сеть
поверх старого компонента.

## Сборка из исходников (если правишь код)

Компонент собирается скриптом `td/build_paint_web.py` и всегда сохраняет свежий
`.tox`. Чтобы TD нашёл исходники, положи их туда, где он их ищет — в папку данных
проекта:

```
<проект>/
  твой_проект.toe
  paint/
    td/     ← содержимое td/ из этого репозитория
    web/    ← содержимое web/ из этого репозитория
    uploads/ media/ tmp/   (создаются сами)
```

Дальше в Textport — один шаг: сборка, самопроверка и диагностика:

```python
exec(open(r"<проект>\paint\td\run_paint_web.py", encoding="utf-8").read())
```

Сводка появится в `paint/tmp/run_summary.txt`, отчёт сборки — в
`paint/td/last_build_report.txt`. Запускать это каждый раз не нужно: компонент при
открытии проекта сверяет отпечаток файлов и пересобирается сам, а пока проект
открыт — проверяет отпечаток каждые 2 секунды (во время мазка пересборка
откладывается).

Тесты (TD не нужен, интерпретатор можно взять из TouchDesigner):

```bash
python td/tests/run_all.py
```

## Требования

- TouchDesigner 2025 — проверено на сборке 2025.32460.
- Браузер с `canvas` (Chrome, Edge, Safari) — на планшете работает.
- Отдельный Python не нужен: тесты гоняются питоном, который идёт вместе с TD.
